# 决赛命题分析与模拟卷设计

> 依据：①赛项通知 ②官方样题（2026-09-02）③《人工智能训练师国家职业技能标准（2021 年版）》④《全国总决赛平台操作手册（测试比赛）》⑤2026-10 初赛试题截图（34 道）
> 前三份在本文件夹，④⑤在赛项资料目录。本文的分析结论是备赛推断，不是官方命题说明。
> 配套实现：`/finals` 决赛模拟平台；卷面数据 `data/finals/`；命题源文件 `scripts/finals/problems/`、`data/finals/theory/`。

## 一、结论先行

1. **决赛 70% 的分值在编程题。** 通知口径是理论 30% + 实操 70%；官方决赛模拟赛的形式是 57 题 / 100 分 / 180 分钟——单选 50 题 × 0.6 分 = 30 分，编程 7 题 × 10 分 = 70 分。备赛时间应按 3 : 7 分配。
2. **编程题是固定主题的「业务测算题」。** 7 道题对应数据处理、标注、数据集、推理容量、人机路由、抽样、告警 7 个主题，都是用 Python 标准库就能完成的列表 / 字典 / 排序 / 统计题，不考深度学习框架。把每个主题的套路练熟，比刷算法题有用。
3. **理论题与初赛同源。** 官方模拟系统的理论题从初赛题库里抽取，另加合规与职业道德情景题。初赛 34 道题反映出的考点分布，就是决赛理论题的复习范围。
4. **5 套模拟卷怎么用。** 每套都按正式赛形式组卷（50 单选 + 7 编程），编程题在 7 个主题上各出一道、5 套互不重复。建议先用练习模式摸清题型，再掐表做全真模拟；交卷后的成绩页会给出逐模块得分、逐测试点结论、解析和参考代码。

## 二、初赛试题分析

### 2.1 题型与来源

拿到的初赛试题是 34 张答题截图，题号不连续（单选编到 48 以后，多选 25 以后，判断 22 以后），说明初赛题库明显大于 34 题，各题型分别编号。

| 题型 | 截图题数 | 题库规模（推断） | 答案形式 |
|---|---|---|---|
| 单选题 | 15 | 48 题以上 | 四选一 |
| 多选题 | 12 | 25 题以上 | 多选、少选、错选均不得分 |
| 判断题 | 7 | 22 题以上 | 正确 / 错误 |

决赛模拟赛的理论部分只有单选题。本模拟卷把初赛的多选、判断题改写成了单选（题面标注「据初赛题改编」），初赛单选题则原样收录（标注「初赛真题」）。

### 2.2 考点分布

把 34 道题按技术领域归类：

| 领域 | 题数 | 涉及知识点 |
|---|---|---|
| 数据分析与统计 | 8 | 轮廓系数、ETL 阶段、漏斗流失率、单因素方差分析、`ROW_NUMBER`、星型模型、Cohen's Kappa、K-means 需预设簇数 |
| 语音技术 | 7 | FastSpeech2 时长预测器、声码器、说话人嵌入、音色克隆主观听感、语音增强环节、ASR 系统构成、流式识别 |
| 模型评估与训练工程 | 5 | 少数类指标、Dropout 推理关闭、精确率与召回率的关系、标签平滑、bfloat16 与 fp16 |
| 产品、交互与可视化 | 5 | 在线交互链路核心模块、图表规范、A/B 实验设计、多模态情感信号、定性用户研究 |
| NLP、对话与检索 | 4 | N-gram 特征、交叉编码器重排、对话管理职责、Transformer 注意力 |
| 视觉与 3D | 3 | NeRF、Blendshape、面部表情驱动 |
| 系统工程 | 2 | 近似最近邻检索、gRPC 与 HTTP/2 |

逐题清单见附录 A。

### 2.3 命题风格

- **业务场景包裹技术考点。** 题干几乎都以「数字人客服 / 播报 / 音色克隆 / 数据分析报告」开头，但考的是通用技术点：读得懂场景，答对靠基础。
- **四个考查层次**：概念辨析（说话人嵌入是什么）、流程归属（字段类型转换属于 ETL 的哪一步）、指标选择（三个版本比满意度用哪种检验）、方案选型（控制眨眼挑眉用哪种形变方案）。
- **难度重心在「选对工具」。** 统计方法、评估指标、3D 表示、检索结构这类「知道什么时候用哪个」的题占多数，需要推导或计算的题少。
- **与标准的关系。** 约 6 成题落在标准三级 / 高级工「业务分析」「智能训练」「智能系统设计」三个职业功能里；TTS、3D、RAG 等属于数字人训练师工种特色，标准原文没有展开，要靠行业知识补。

## 三、官方决赛模拟赛的形式与判分口径

来自《平台操作手册（测试比赛）》，本模拟平台逐条对照实现。

| 项目 | 官方口径 |
|---|---|
| 题量与分值 | 57 题，满分 100：单选 50 题 × 0.6 分，编程 7 题 × 10 分 |
| 时长 | 180 分钟，中途不可暂停，计时结束自动提交 |
| 编程题判分 | 函数模板题，每题 10 个测试点、每个 1 分，全部通过得满分 |
| 运行限制 | 单次运行 5 秒，内存 128 MB；数值处理使用 Python `round` |
| 反馈 | 提交结果只显示通过 / 错误，不展示逐点得失；自测运行只跑可见样例 |
| 环境 | 编辑器页签为 Python (3.8.1)，可恢复初始状态，有「测试用例」「测试结果」页签和「自测运行」「提交」按钮 |
| 切屏 | 累计 3 次自动交卷 |
| 成绩 | 交卷后不显示成绩 |

官方模拟赛的 7 道编程题标题：

| 题号 | 标题 | 一句话概括 |
|---|---|---|
| 51 | 数据处理流程关键路径与瓶颈判定 | 带依赖的流程图上求最长路径 |
| 52 | 多标注员标签合并与仲裁 | 多人投票、按权重或准确率裁决 |
| 53 | 训练测试集分组泄漏检查 | 同一组样本不得跨训练集与测试集 |
| 54 | 推理服务容量测算与降级决策 | 按显存、并发、时延算副本数或降级档位 |
| 55 | 人机协同路由阈值测算 | 置信度阈值与自动应答率、准确率、成本的权衡 |
| 56 | 分层抽样配额分配 | 按比例或尼曼分配，处理余数与下限 |
| 57 | 告警聚合抑制与值班负载测算 | 时间窗口聚合、抑制规则、响应时效统计 |

共同特征：输入是列表 / 字典 / 数值，输出是数值、列表或字典；要处理边界（并列、空输入、下限）；通常有一次排序、一次聚合或一次滑动窗口。没有输入输出流，不需要读文件。

## 四、命题蓝图

蓝图文件：`data/finals/blueprint.json`。

### 4.1 理论题（50 题 / 套）

| 模块 | 题数 | 占比 | 依据与考虑 |
|---|---|---|---|
| 职业道德与基础知识 | 6 | 12% | 标准 2.1、2.2；决赛模拟赛新增合规情景题，所以比标准权重（5% + 10% 中的理论部分）略高 |
| 数字人专项 | 10 | 20% | 工种特色：TTS、ASR、3D、多模态、RAG 与大模型、人格设定 |
| 业务分析 | 8 | 16% | 标准 3.3 之 1：业务流程、数据仓库、SQL、统计方法 |
| 数据处理与标注 | 6 | 12% | 标准 3.3 之 2.1：清洗规范、标注类型、一致性指标 |
| 智能训练 | 7 | 14% | 标准 3.3 之 2.2：数据集划分、评价指标、训练与错误分析 |
| 智能系统设计 | 11 | 22% | 标准 3.3 之 3：可视化、人机交互流程、监控与工程 |
| 培训与指导 | 2 | 4% | 标准 3.3 之 4 |

- 标准三级 / 高级工的理论权重是职业道德 5、基础知识 10、业务分析 20、智能训练 30、智能系统设计 30、培训与指导 5。决赛题库更偏数字人工种，所以单列 20% 的「数字人专项」；「智能训练」「智能系统设计」的一部分内容（数据集维护、容量测算、监控）移到了编程题里考，理论题占比相应下调。
- 难度：1 级（记忆识别）20 题、2 级（理解应用）20 题、3 级（分析计算）10 题。
- 答案位置：A / B / C / D 各 8–17 次，避免规律。
- 题目来源：初赛单选原题（`prelim`）15 道、初赛多选 / 判断改编（`prelim_adapted`）17 道、原创（`original`）218 道。
- **初赛 15 道单选题全部原样收录**，每道只出现一次：第 1 套 5 道、第 2 套 3 道、第 3 套 2 道、第 4 套 3 道、第 5 套 2 道。初赛的 12 道多选题和 7 道判断题里有 17 道改写成了单选题；其余 2 道（对话管理、Transformer 注意力）在第 1 套里有同知识点的原创题。
- 除初赛原题外，各套的考点互不重复；初赛原题考的知识点，别的套里可能另有原创题从不同角度考（例如第 1 套的「Kappa 解读」与第 4 套的初赛原题「选哪个一致性指标」）。

### 4.2 编程题（7 题 / 套）

- **一题一主题，五套五变式。** 每套 7 道题依次对应官方的 7 个主题（题号 51–57 与官方一致），5 套共 35 道题在主题内互不重复，难度与官方模拟赛相当。
- **每题 10 个测试点。** 第 1 个是可见样例；其余覆盖边界（空输入、并列、阈值相等）、陷阱（浮点余数、四舍五入方向、时间窗口边界）和 1–2 个大规模用例。
- **只用标准库。** 参考解只用到 `math`、`collections` 等标准库，Python 3.8 也能运行。

### 4.3 关于官方样题参考答案的提醒

官方样题 PDF 的参考答案表把第 17–45 题全部标成了 A，显然不能逐题照搬。其中「远程智能诊疗是通过什么方式」一题，样题答案表给的是「患者的视频」，而考纲清单写的是「电子病历」，两者冲突。本模拟卷只收录了答案没有争议的样题考点（业务流程梳理的目的、分词质量标准、实体标注、硬件产品的设计内容等），有冲突的那道没有收录。备考时遇到这类题，以国家标准的原文和教材为准，不要只记样题答案表里的字母。

## 七、质量保障

每道编程题在 `scripts/finals/problems/setN.py` 里声明，构建时逐项校验，任何一项不过就构建失败：

| 校验项 | 做法 | 抓到过的问题 |
|---|---|---|
| 参考解生成期望输出 | 参考解跑 10 个测试点 | — |
| 独立实现交叉验证 | 每题另写一份思路不同的实现（暴力、分数运算、逐时间步模拟），10 个测试点结果必须一致 | 第 4 套第 57 题参考解与独立实现都漏了「按时间排序」 |
| 差分测试 | 参考解与独立实现对 400 轮随机入参逐一比对 | 同上，由随机用例发现 |
| 典型错解必须失分 | 每题 3–5 份「像样但错」的解法，每份至少挂 1 个测试点 | 第 4 套第 53 题「未排序」错解曾通过全部测试点 |
| 参考代码自包含 | 把参考代码放进干净命名空间重跑 | 第 5 套第 53 题依赖了题面外的辅助函数 |
| 题面排版 | 题面里不能有会被渲染进同一段落的相邻行 | 第 1 套示例代码被渲染成一行 |

理论题的校验分两步。先是结构校验：模块配额、难度分布、答案字母范围、选项数量与重复、解析长度、依据条款写法、套内考点不重复、跨套题干不重复。定稿前再做**独立盲答**：把 250 道题去掉答案和解析，交给看不到标准答案的「考生」逐题作答，再与标准答案比对。首轮 250 题中有 2 题答案不一致、另有十几题被标了「有保留」，逐条过目后撤换了 2 题（依据有冲突的「远程智能诊疗」；两位盲答者都不认同答案的「属性标注」，它源自样题里一道答案不可靠的题），修正了若干解析和依据条款；第 1 套另有 5 道与初赛原题知识点重复的自创题被换成了新考点。改动和新增的题目又做了一轮盲答，全部一致。

构建完成后还可以用线上判题内核再体检一遍（`node scripts/finals/check.mjs`）：参考解必须 10 / 10，起始模板必须 0 / 10，死循环必须判超时。这一步已接入 `.github/workflows/content-audit.yml`。

## 八、平台使用

入口：首页「决赛模拟」卡片，或访问 `/finals`。

| 功能 | 说明 |
|---|---|
| 全真模拟 | 180 分钟计时、切屏 3 次自动交卷、到时自动交卷、正式提交只显示逐点结论 |
| 练习模式 | 不限时、不判切屏、提交后可看运行错误信息 |
| 答题 | 单选 50 题 + 编程 7 题；草稿自动保存，刷新或误关页面后可从入口页继续 |
| 编程题 | 题面与示例、代码编辑器（Python）、「自测运行」只跑样例、「提交」判 10 个测试点 |
| 成绩页 | 总分、理论 / 编程分项、逐模块得分率、逐题测试点结论、解析、你的代码与参考代码、薄弱点 |
| 编程题专项练习 | `/finals/code`，按主题分组，单题练习，提交后展示每个测试点的输入与期望 |

常用命令：

```bash
python3 scripts/finals/build.py              # 由源文件生成 5 套卷（data/finals/sets/）
python3 scripts/finals/build.py --check      # 检查生成物与源文件一致
node scripts/finals/check.mjs                # 体检：一致性、卷面结构、线上判题实跑
```
